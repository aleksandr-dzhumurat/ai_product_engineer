# План рефакторинга скрейперов

Цель — удалить неиспользуемый код и сократить дублирование, не меняя CLI, порядок шести этапов WikiArt, форматы выходных файлов и ключи существующего кэша. Проверки запускаем на фикстурах или в отдельном `--data-dir`, не трогая `data/artworks/`.

## Этап 1. Удалить устаревший код

- [x] Проверить ссылки из кода, тестов, ноутбуков и Makefile перед удалением.
- [x] Удалить старый путь `get_artwork()` → `get_artworks_info()`, неиспользуемую модель `Artwork` и закомментированные реализации сбора работ через батчи.
- [x] Удалить пустую `utils.prepare_service_data()`, сохранив реализацию в `scrape_wikiart.py`.
- [x] Удалить неиспользуемые `get_artworks_json()`, `get_tags()`, `get_popular_artists()` и `init_nltk()`. Сохранить `is_popular` в выходном CSV и необязательный `popular_artists` у `get_artists_pages()`.

Проверка: интеграционный тест WikiArt проходит без изменения ожидаемых результатов.

## Этап 2. Объединить дубли WikiArt

- [x] Вынести селекторы основного и запасного изображения в общий парсер. Оставить нормализацию URL у вызывающего кода и сохранить схему полей `image`, `image_url` и `images`.
- [x] Строить URL списка работ `…/all-works/text-list` в одном месте для скачивания и вычисления пути к кэшу.
- [x] Вынести общую обвязку параллельной загрузки и прогресса из `get_artworks_raw_html()` и `prepare_artists_index()`. Решения об обработке неудачных загрузок оставить в вызывающих функциях.

Проверка: тесты покрывают основное и запасное изображение, относительный URL, отсутствие изображения и сбой одной загрузки. Порядок этапов и выходные форматы не меняются.

## Этап 3. Убрать дубли в общих утилитах и разделить модули

- [ ] Вынести запись одной JSONL-строки для `append_run()` и `push_event()`, сохранив поля событий и журнала.
- [ ] Вынести общий итератор журнала для `load_logged_links()` и `load_mhtml_ids()`, сохранив пропуск пустых и битых строк. Оставить `read_jsonl()` для датасета WikiArt строгим.
- [ ] Убрать `logging.basicConfig()` при импорте и явно настраивать логирование в точках входа через `configure_logging()`.
- [x] Перенести функции WikiArt в существующий `src/scraping/scrape_wikiart.py`, оставив в `utils.py` общие функции и функции блогов. Деплой блогов не зависит от `scrape_wikiart.py`.
- [ ] После завершения запущенного до переноса прогона удалить временный `utils._process_artwork_file`: старый процесс использует этот путь для запуска воркеров.

Проверка: прямой запуск WikiArt и запуск через `python -m`, парсинг в двух процессах, чтение и запись журнала блогов.

## Отдельные исправления после рефакторинга

Ключи кэша, ограничения очереди, политика повторов HTTP, атомарная запись и отчёт о потерях меняют поведение. Их лучше делать отдельно, чтобы не смешивать с очисткой и переносом кода.
